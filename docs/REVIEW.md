# 프로젝트 리뷰 — 2026-10-23

기준 커밋: `20d2737` (Haiku 5.5 단가 추가). 수집기/설정/커서, 에이전트와 오프라인 큐, SQLite/HTTP API, 웹 상태 관리/화면, 설치 경로와 CI를 검토했습니다. 테스트는 운영과 분리된 로컬 서버 및 샘플 데이터로 수행했습니다.

## 발견과 개선

| 영역 | 발견한 문제 | 개선 |
|---|---|---|
| 전송 | 408/429를 영구 실패로 분류하여 큐 flush가 보류 데이터를 삭제할 수 있음 | 제한된 재시도 후 큐에 보존, 복구 후 정상 전달 검증 |
| 수신 확인 | 잘못된 HTML 2xx 응답, 중간에 끊긴 본문도 전달 성공으로 처리 | JSON 파싱·본문 읽기·1 MiB 응답 상한 확인 후 성공 처리 |
| 재동기화 | 일부 큐 전송이 성공한 후 다른 배치가 실패하면 이미 받은 resync 지시를 놓침 | 부분 성공의 통계와 지시를 실패 여부와 독립적으로 유지 |
| 입력 | 음수 reasoning 토큰이 유효한 이벤트로 통과 | 저장 전 유효성 검사에서 거부 |
| DB | 초기 마이그레이션 실패 시 별도 읽기 풀 정리 누락, 설명이 이전 단일 연결 구조를 가리킴 | 전체 핸들 정리와 현재 구조 문서화 |
| 이벤트 화면 | 중복 페이지 요청/겹치는 이벤트, 필터 변경 후 이전 요청의 오류가 새 화면에 반영됨 | `useEventFeed`로 책임 분리, 요청 식별·중복 제거·오래된 결과/오류 무시 |
| API 클라이언트 | 후보 토큰 검증의 401이 활성 세션까지 무효화, reload 응답 타입 불일치 | 후보 검증과 세션 만료 처리 구분, 실제 응답 타입 적용 |
| 가격표 | 적용 기간이 다른 같은 모델의 React 행 키가 충돌 | 모델+적용 기간으로 식별, 정렬/재로드 브라우저 검사 |
| 설치 | 해시가 없으면 검증을 건너뜀, 서버 fallback은 별도 구현이며 해시 확인도 없음 | 해시 필수화, Unix 원본을 서버에서도 공유, 기본 URL을 셸 리터럴로 인용 |
| 검증 체계 | 웹 단위 테스트 위주이며 실제 브라우저 동작과 설치 실패 경로가 자동 검사되지 않음 | Playwright·설치 실행 테스트·GitHub CI·기여 규칙 추가 |
| 테스트 격리 | 기본 통합 테스트가 개발자의 실제 홈 로그를 자동으로 읽고 실행 시간이 데이터 양에 따라 변함 | 실제 홈 검사는 `AI_USAGE_INTEGRATION=1`일 때만 실행, 일반 검증은 고정 픽스처 사용 |

정상 요청/정상 설치의 결과와 기존 화면을 유지하고, 위 오류 경로를 의도적으로 교정했습니다. UI 마크업/스타일/문구를 재디자인하지 않았습니다.

## 동일성 검증

- 같은 DB에 기기 2개, 소스 3개, 이벤트 240개, 단가가 알려진/알려지지 않은 모델과 다운로드 목록을 준비했습니다.
- 기기·가격표·이벤트·요약 및 5개 차원의 breakdown/timeseries/throughput **19개 API JSON**을 변경 전후 비교합니다.
- 로그인, 개요, 에이전트, 모델, 프로젝트, 기기 사용량, 기기 관리, 이벤트, 가격표, 다운로드 **10개 화면**을 1440×1000/390×844와 라이트/다크 조합으로 비교합니다. 시간·데이터·글꼴·브라우저를 고정하고 **40개 기준 이미지**를 변경 전 서버에서 생성했습니다. 허용 픽셀 차이는 0입니다.
- 브라우저 동작 검사는 5개 시나리오를 네 환경에서 실행합니다. 기기 작업은 생성부터 이름 변경·재동기화·초기화·재발급·폐기·확인 문구 입력 후 삭제까지 포함합니다.
- 전송 재시도/부분 재동기화, 페이지 요청 경합, 후보 토큰 검증, 설치의 정상·해시 누락/손상/불일치 경로에 회귀 테스트를 추가했습니다.

실행 방법은 [CONTRIBUTING.md](../CONTRIBUTING.md)에 있습니다. 픽스처는 loopback과 비어 있는 샘플 DB만 허용하고 실제 로그·운영 토큰을 읽지 않습니다.

## 범위와 남은 사항

이 검증은 지정한 Chromium, 두 화면 크기, 두 테마, 샘플 데이터에서의 동일성을 확인합니다. 모든 브라우저/기기/데이터 조합에서의 무결함을 뜻하지 않습니다. Linux/macOS/Windows 에이전트의 여섯 OS/아키텍처 조합을 크로스 빌드하지만 각 OS의 실제 서비스 매니저 설치는 이 검증에서 수행하지 않습니다. PowerShell 설치 테스트도 파일 교체·검증 로직을 실행하고 서비스·다운로드는 모킹합니다.

설치 파일과 manifest가 같은 서버에서 제공되는 구조는 유지됩니다. 이번 해시 필수화는 손상·누락 검증이며 독립된 서명 기반 공급망 검증을 대신하지 않습니다. 웹 JS 번들은 여전히 약 1.1 MB이며 코드 분할 최적화는 별도 성능 작업입니다.
